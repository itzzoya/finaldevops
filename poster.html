1. Background
Traditional institutional hostel operations rely heavily on manually updating spreadsheets or monolithic software infrastructures. These practices present persistent real-time coordination challenges across rooms, bookings, and billing pipelines. This project addresses these limits by building a robust cloud-native system.
2. Problem Statement
Manual operations introduce configuration errors, inconsistent system state parameters, billing overhead risks, and prolonged delays in deployment iteration cycles. The absence of automation patterns slows feature scaling and leads to operational delivery drops during peak booking timelines.
3. Objectives
  • Automate build and container staging.
  • Isolate execution steps via clean Docker layers.
  • Deploy predictable runtimes using Kubernetes.
  • Eliminate configuration errors across staging.
  • Ensure end-to-end operational transparency.
4. Requirement Specs
Hardware Stack: Intel i5/equivalent, Minimum 8 GB RAM base configuration, 50 GB storage space allocation.

Software Stack: Ubuntu LTS Base Engine, Docker Suite v24+, Kubernetes Pod Cluster Control, Git Core, and Node.js execution runtimes.
5. Functional Requirements
  • Automated Git webhook triggering mechanics.
  • Isolated multi-stage container target compilations.
  • Zero-downtime microservice instance scheduling.
  • Persistent monitoring loop configurations.
  • Rollback options for build state targets.

7. DevOps Workflow
  • Push: Microservice edits reach GitHub core main.
  • Trigger: Active webhooks call automation loops.
  • Build: Base Docker stages generate standard runtimes.
  • Deploy: Target configurations mount inside active K8s nodes.
